Why the static URDF file alone can't do this: the knee's true angle is a nonlinear function of both hip angles — a bolt-hole ring closing an arc, not a straight line. URDF's only joint-coupling mechanism, <mimic>, is strictly linear (position = multiplier × other + offset), and fitting the best possible line through this relationship misses by up to 370 mm at ±60–80° — try Manual mode above to see the same effect happen live. A viewer that drags one joint at a time can never enforce this constraint; only a program that reads both hip values and re-solves the closure can, which is what this page and five_bar_state_publisher.py both do.
